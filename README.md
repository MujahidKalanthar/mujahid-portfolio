## 🖼️ Overview

This is the **production portfolio** of **Mujahid Kalanthar** — a third-year ECE undergraduate at MNNIT Allahabad building production-grade systems across full-stack engineering, AI/RAG architectures, and data analytics. The portfolio itself is an editorial-grade web experience built with **React 19 + TypeScript + Vite**, deployed on Vercel.

It is not a simple card list. It is an immersive, section-rich application featuring animated page transitions, an interactive India journey map, a competitions archive with 27 national events, a pitch deck library, a literary room, a poetry carousel, and an executive recruiter drawer — all running as a single performant SPA.

## 🛠️ Running Locally

```bash
# 1. Clone the repository
git clone https://github.com/MujahidKalanthar/mujahid-portfolio.git
cd mujahid-portfolio

# 2. Install dependencies
npm install

# 3. Start the dev server (runs on http://localhost:3000)
npm run dev

# 4. Build for production
npm run build

# 5. Preview the production build locally
npm run preview
```

> **Requirements:** Node.js ≥ 18, npm ≥ 9

## 🎯 Architecture Decisions

**Why no CSS framework?** The portfolio uses structured inline-style composition and a minimal global stylesheet. This eliminates unused class bloat (~200KB+ Tailwind purge overhead), gives pixel-precise control over the editorial aesthetic, and keeps bundle size minimal.

**Why Framer Motion?** The cinematic welcome intro, animated hero taglines, modal transitions, and scroll-reveal effects require a physics-based animation engine. Framer Motion's layout animations handle component mount/unmount sequences cleanly with zero manual keyframe management.

**Why D3-Geo + TopoJSON for the map?** The journey map renders India with 14 pinpointed cities from competition archives. A static image would not support interactive hover tooltips, dynamic coordinate plotting from data, or future route-line animations. The D3 projection pipeline gives deterministic coordinate-to-pixel mapping.

**Why all data in TypeScript files?** Centralizing all content in typed data modules (`portfolioData.ts`, `competitionsData.ts`) means updating content requires zero component-level changes. The TypeScript interfaces enforce schema contracts at compile time.
